## 2. SpinQuant side (main)

Source: `README.md`, `utils/process_args.py`, `ptq.py`, `optimize_rotation.py`, `eval_utils/modeling_llama.py`, `scripts/*.sh`.

- Officially scripted families (README.md:50-55): "LLaMA-2 7B/13B and LLaMA-3 8B" via `scripts/10_optimize_rotation.sh`, "LLaMA-2 70B and LLaMA-3 70B" via `scripts/11_optimize_rotation_fsdp.sh`; PTQ eval via `scripts/2_eval_ptq.sh`. Exact IDs referenced in README examples: `meta-llama/Llama-2-7b`, `meta-llama/Llama-2-70b` (README.md:52,55; note these are written without the `-hf` suffix — the actual HF-format repos are meta-llama/Llama-2-7b-hf etc.). ExecuTorch path additionally targets Llama-3.2-1B/3B-Instruct (README.md:19,70; `scripts/31_optimize_rotation_executorch.sh`, `scripts/32_eval_ptq_executorch.sh`), including tie_word_embeddings handling in ptq.py:34-38 and optimize_rotation.py:54.
- Model loading is architecture-generic within Llama: `ptq.py:31-45` does `AutoConfig.from_pretrained(input_model, token=access_token)` then `eval_utils.modeling_llama.LlamaForCausalLM.from_pretrained(input_model, config=config, token=access_token)`; tokenizer is `LlamaTokenizerFast.from_pretrained(input_model)` (ptq.py:55-64). `--input_model` is a free-form string (utils/process_args.py:20-22). **Nothing restricts to base (non-chat) models** — meta-llama/Llama-2-7b-chat-hf has the identical LlamaConfig/architecture as Llama-2-7b-hf and loads through the exact same path. Calibration/eval is WikiText-2 PPL (ptq.py:68-76), which runs on chat models too (scores just differ).
- Vicuna also loads through this path (LlamaForCausalLM, llama tokenizer). `utils/hadamard_utils.py:16-79 get_hadK` even carries explicit branches for **llama-1** dims ("llama-1-30b intermediate", "llama-1-13b intermediate", n%172 for llama-1-7b-style 11008=172*64), so LLaMA-1-based Vicuna-v1.3 hidden/intermediate sizes are covered; Vicuna-v1.5 is Llama-2-based (identical dims to Llama-2).
- Pre-optimized rotation matrices: YES — README.md:119: "You can download the optimized rotation matrices here" -> Google Drive folder https://drive.google.com/drive/folders/1R2zix4qeXBjcmgnJN1rny93cguJ4rEE8?usp=sharing, covering the models in the results table: LLaMA-3 8B, LLaMA-3 70B, LLaMA-2 7B, LLaMA-2 13B, LLaMA-2 70B (README.md:93-117). These are for the BASE models; for a chat model (or Vicuna) you would run `scripts/10_optimize_rotation.sh` yourself (or start from `--rotate` with random/hadamard R, process_args.py:88-89: random rotation used if no path given).
- Gated-repo auth is built in: README.md:47 "For gated repo such as meta-llama, you can set your HF token to `access_token`"; `--access_token` plumbed through process_args.py:29-32 into every from_pretrained call.
- Mixtral: NOT supported (only modeling_llama.py / modeling_llama_quant.py exist).
- Pinned stack: transformers==4.44.2 (requirement.txt) vs EAGLE v1 transformers==4.36.2 — the two pipelines should run in separate envs or the pin reconciled.

## 4. Tokenizer/config compatibility — top candidate (Llama-2-7b-chat + yuhuili/EAGLE-llama2-chat-7B)

- Draft config match: `eagle/train/llama_2_chat_7B_config.json` (the in-repo mirror of the yuhuili draft config) has hidden_size=4096, intermediate_size=11008, num_attention_heads=32, num_key_value_heads=32, vocab_size=32000, max_position_embeddings=4096, num_hidden_layers=1 — exactly matching meta-llama/Llama-2-7b-chat-hf. `ea_model.py:35-39` derives hidden/vocab size from the target's lm_head (`base_model.lm_head.weight.shape`) and loads the draft via `EConfig.from_pretrained(ea_model_path)`; `configs.py` defaults (hidden 4096 / vocab 32000) are the LLaMA-7B geometry. The draft reuses the target tokenizer: `ea_model.py:38` `AutoTokenizer.from_pretrained(self.base_model_name_or_path)` — no separate draft tokenizer, so tokenizer identity is guaranteed.
- Same HF ID into SpinQuant: `bash scripts/10_optimize_rotation.sh meta-llama/Llama-2-7b-chat-hf 4 4 4` then `bash scripts/2_eval_ptq.sh meta-llama/Llama-2-7b-chat-hf 4 4 4` — `--input_model` is passed verbatim to AutoConfig/LlamaForCausalLM/LlamaTokenizerFast `.from_pretrained` (ptq.py:31-64). tie_word_embeddings is False for Llama-2, so the 3.2-specific lm_head clone (ptq.py:34-38) is a no-op.
- Gated access (document, don't bypass): meta-llama/Llama-2-* requires (1) accepting Meta's license on the Hugging Face model page, (2) an HF access token; SpinQuant consumes it via `--access_token <token>` (README.md:47, process_args.py:29-32); EAGLE uses standard huggingface_hub download (`hf_hub_download`, ea_model.py:95,103) which picks up `huggingface-cli login` / `HF_TOKEN` env. The yuhuili/EAGLE-llama2-chat-7B draft repo itself is NOT gated.
- Memory sanity on one RTX 4090 24GB: EAGLE fp16 eval = 7B target (~13.5GB) + 0.24B draft (~0.5GB) + tree KV cache — fits. SpinQuant `2_eval_ptq.sh` (single-GPU torchrun) fits; `10_optimize_rotation.sh` defaults to 8 GPUs (`--nproc_per_node=8`) but is data-parallel and can be reduced to 1 GPU for a 7B model with bf16 + gradient checkpointing (already enabled in the script), or the published base-Llama-2-7B rotation from the Google Drive folder can be used as a starting point/ablation.
- Env caveat: EAGLE v1 pins transformers==4.36.2 / torch==2.0.1 (requirements.txt); SpinQuant pins transformers==4.44.2 (requirement.txt) — use separate virtualenvs.
