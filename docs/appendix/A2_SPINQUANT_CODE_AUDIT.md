## 1. Rotation set R1–R4

All rotations follow the QuaRot scheme with R1/R2 made learnable (paper: Cayley-optimized).

### R1 — global residual-stream rotation (hidden_size x hidden_size)
- **Learned** (Cayley/Stiefel SGD, see Q2) or random Hadamard fallback: `eval_utils/rotation_utils.py:124` (`get_orthogonal_matrix(model.config.hidden_size, args.rotate_mode)`), overridden by trained checkpoint at `:125-127` (`R1 = torch.load(R_cpk)["R1"]`).
- **Fused offline** into weights at PTQ time (`rotate_model`, `eval_utils/rotation_utils.py:122-147`, `@torch.inference_mode()`), no runtime op:
  - `rotate_embeddings` (`:55-60`): `embed_tokens.weight = W @ R1` — token embeddings emitted already in R1 basis.
  - `rotate_attention_inputs` (`:63-68`): `q_proj/k_proj/v_proj.weight = W @ R1` (input-side, undoes R1 on incoming activations).
  - `rotate_attention_output` (`:71-80`): `o_proj.weight = R1.T @ W` (and bias `R1.T @ b`) — attention output re-enters residual in R1 basis.
  - `rotate_mlp_input` (`:83-89`): `up_proj/gate_proj.weight = W @ R1`.
  - `rotate_mlp_output` (`:92-103`): `down_proj.weight = R1.T @ W` (output back into R1 basis), **plus** `apply_exact_had_to_linear(W, had_dim=-1, output=False)` at `:98-100` = the R4-inverse folded into down_proj's input dim.
  - `rotate_head` (`:106-111`): `lm_head.weight = W @ R1` (consumes R1-basis hidden states).

### R2 — per-layer, per-head V/O rotation (head_dim x head_dim, 128 for LLaMA)
- **Learned** per layer; loaded from checkpoint keys `model.layers.{idx}.self_attn.R2` (`eval_utils/rotation_utils.py:138-142`), else random Hadamard of size `head_dim` (`:142`).
- **Fused offline** by `rotate_ov_proj` (`:114-119`): `apply_exact_had_to_linear(v_proj, had_dim=head_dim, output=True, R2=R2)` rotates each head's output slice of `v_proj` by R2, and `apply_exact_had_to_linear(o_proj, had_dim=head_dim, output=False, R2=R2)` rotates `o_proj`'s per-head input dims (`utils/hadamard_utils.py:144-179`, R2 replaces the Hadamard at `:166-167`). Sits between V and o_proj; V-cache is therefore quantized in the R2 basis. No online op.

### R3 — post-RoPE Q/K head-dim rotation
- **Fixed Hadamard, applied ONLINE at runtime**, never fused (it cannot be — it sits after RoPE). Only activated when `k_bits < 16` (`eval_utils/main.py:137-155`).
- Implementation: `QKRotationWrapper` (`eval_utils/rotation_utils.py:150-206`) is monkeypatched to wrap the direct call of `apply_rotary_pos_emb` inside `self_attn.forward` (`add_qk_rotation_wrapper_after_function_call_in_forward`, `:209-228`; generic machinery in `utils/monkeypatch.py:33-50` which rebinds the function name in the method's globals). The RoPE call site in the custom model is `eval_utils/modeling_llama.py:487-489`, i.e. R3 runs **post-RoPE**, before the KV cache update at `:491-496`.
- It applies `HadamardTransform.apply(q)/sqrt(head_dim)` and same to k over the **last dim = head_dim** (`rotation_utils.py:182-183`; `HadamardTransform` = Dao-AILab `fast_hadamard_transform` CUDA kernel, `utils/utils.py:18,39-48`), so Q·Kᵀ is preserved; then K is fake-quantized (token-wise or head-wise per `k_groupsize`, `:186-202`). `k_pre_rope` raises NotImplementedError (`eval_utils/main.py:138-139`, `utils/process_args.py:250`).

### R4 — down_proj input rotation (intermediate_size)
- **Fixed Hadamard, split**: the inverse is **fused offline** into `down_proj` weights (`rotate_mlp_output`, `rotation_utils.py:98-100`; training-side `train_utils/apply_r3_r4.py:24-29`), and the forward Hadamard is applied **ONLINE** to the activation entering down_proj: `eval_utils/main.py:34-40` sets `qlayers[name].online_full_had = True` with `had_K, K = get_hadK(intermediate_size)`; executed in `ActQuantWrapper.forward` (`utils/quant_utils.py:249-255`) via `matmul_hadU_cuda` (`utils/hadamard_utils.py:128-137`; for 11008 = 172·64 it uses the had172 Kronecker factor, `:18-22`). Crucially the online Hadamard happens **before** `quantizer.find_params/quantize` (`quant_utils.py:283-286`), so the down_proj input is quantized in the Hadamard basis. Not learned.

Summary table: R1 learned+fused-offline; R2 learned+fused-offline (per layer, per head); R3 fixed Hadamard, online, post-RoPE on Q and K over head_dim; R4 fixed Hadamard, online on down_proj input over intermediate_size with inverse fused into W_down.

## 2. Rotation optimization (optimize_rotation.py)

- **What is trained: R1 + all per-layer R2 only.** `optimize_rotation.py:70-71` freezes every model parameter; `:72-79` attaches `model.R1 = RotateModule(random_hadamard_matrix(hidden_size))` and `model.model.layers[i].self_attn.R2 = RotateModule(...)` (head_dim); `:104-107` builds `trainable_parameters = [model.R1.weight] + [R2 weights]`. R3/R4 are applied but fixed (`train_utils/main.py:22-34` calls `apply_r3_r4.rotate_model` which only folds R4 into down_proj; R3 wrapper added at `:85-103`).
- **Objective: next-token cross-entropy on wikitext-2 with a fake-quantized (STE) forward in the loop.** The training model `train_utils/modeling_llama_quant.py` applies R1 to embeddings at runtime (`:1090-1094`), passes R1 into every `QuantizeLinear` (`:460-462, 538, 866, 874`), applies `R1.T` before lm_head (`:1377-1385`), and computes standard CE loss (`:1406-1418`). `QuantizeLinear.forward` (`train_utils/quant_linear.py:22-56`) multiplies the weight by R1/R2 in float64 **inside the forward**, then fake-quantizes it via the attached `WeightQuantizer` (attached by `train_utils/rtn_utils.py:44-52`, RTN + optional MSE clip when `--w_clip`); activation/KV quantizers use `STEQuantize`/`AsymSTEQuantize` (straight-through backward, `utils/quant_utils.py:61-84`), so gradients flow to R1/R2 through the quantized network.
- **Optimizer: Cayley SGD on the Stiefel manifold** — `SGDG(trainable_parameters, lr=training_args.learning_rate, stiefel=True)` (`optimize_rotation.py:109`; `train_utils/optimizer.py:57-199`, `Cayley_loop` at `:33-39`, from the "Optimization-on-Stiefel-Manifold-via-Cayley-Transform" repo). Not RiemannAdam. HF `Trainer` (or `FSDPTrainer` when `--fsdp` set, `:110-113`).
- **Steps/dataset**: `--max_steps 100`, `--learning_rate 1.5`, cosine schedule, per-device batch 1, seq len 2048; data = `Salesforce/wikitext, wikitext-2-raw-v1` train split via `CustomJsonDataset` (`optimize_rotation.py:95-102`, `utils/data_utils.py:46-103`).
- **Saved checkpoint**: `torch.save(R_dict, output_rotation_path/"R.bin")` where keys are `R1` and `model.layers.{i}.self_attn.R2` (state-dict keys with `.weight` stripped, `optimize_rotation.py:132-143`) — exactly what `rotate_model` loads at PTQ time (`eval_utils/rotation_utils.py:127,139-140`).
- **Script args**: `scripts/10_optimize_rotation.sh` runs `torchrun --nnodes=1 --nproc_per_node=8 optimize_rotation.py` with `--w_bits $2 --a_bits $3 --k_bits $4 --v_bits $4 --w_clip --a_asym --k_asym --v_asym --k_groupsize 128 --v_groupsize 128 --bf16 True --gradient_checkpointing True --max_steps 100` (`:10-36`) — i.e. **quantization is active during rotation optimization at the target bit widths** (e.g. W4A4KV4). `scripts/11_optimize_rotation_fsdp.sh` is identical plus `--fsdp "full_shard auto_wrap" --fsdp_transformer_layer_cls_to_wrap 'LlamaDecoderLayer'` (`:36-37`) — intended for 70B (README:53-55). README:72-73 notes that when GPTQ will be used at PTQ, rotations should be optimized with weights unquantized (`w_bits 16`).
- **GPU memory**: optimization requires **full-model backprop** (loss at lm_head, gradients chained through all 32 layers to reach R1 at the embedding; weights frozen but activations gradients required). With bf16 7B weights (~13.5 GB), gradient checkpointing on, batch 1 × 2048, plus transient float64 weight copies made per-linear in `QuantizeLinear` (largest: 4096×11008 fp64 ≈ 0.36 GB each) and fp32 logits (~0.5 GB), the peak is roughly 18–22 GB — a single 24 GB RTX 4090 is **marginal/borderline** (may fit at bs=1 with checkpointing, may OOM). The reference script assumes 8 GPUs but uses plain DDP for ≤13B, which replicates the full model per GPU (no per-GPU memory reduction — only throughput); FSDP (script 11) is what actually shards memory and is needed for 70B.

## 4. FAKE vs REAL quant (critical)

**Everything executed in PyTorch is FAKE quant (quantize-dequantize); all matmuls remain FP16/BF16.**
- `ActQuantizer.forward` returns `STEQuantize/AsymSTEQuantize` output = `scale * clamp(round(x/scale)...)`, i.e. dequantized floats (`utils/quant_utils.py:104-110, 61-84`).
- `ActQuantWrapper.forward` quantize-dequantizes the input then calls the ordinary FP `self.module(x)` (`quant_utils.py:283-290`).
- GPTQ/RTN write dequantized FP weights back into `weight.data` (`eval_utils/gptq_utils.py:154-156, 352-353`); `WeightQuantizer.fake_quantize` is literally named so (`quant_utils.py:473-480`).
- `QuantizeLinear.forward` (train path) ends in `nn.functional.linear(input, weight, bias)` on fake-quantized FP weights (`train_utils/quant_linear.py:56`).
- **There is NO INT4 (or any low-bit) GEMM kernel anywhere in the repo.** The only custom CUDA is the external `fast_hadamard_transform` package (FP transform, `utils/utils.py:18`). Integer tensors appear only as `int_weight`/`scale` buffers registered for export (`gptq_utils.py:149-153, 354-356`).
- **ExecuTorch path**: `scripts/31_optimize_rotation_executorch.sh` optimizes rotations at `--w_bits 16 --a_bits 8 --w_groupsize 32`; `scripts/32_eval_ptq_executorch.sh` runs ptq.py with `--w_bits 4 --a_bits 8 --w_groupsize 32 --export_to_et --save_qmodel_path .../consolidated.00.pth`. Export = **W4 (group-wise, g=32; README says g=256 for 8B) + 8-bit dynamic activations**, with embed_tokens/lm_head RTN-quantized to 8-bit per-channel (`eval_utils/main.py:65-72`, `gptq_utils.py:339-341`). `utils/convert_to_executorch.py:37-271` repacks `*.module.int_weight`/`scale` into Meta/llama consolidated format and `sanitize_checkpoint_from_spinquant` (`:273-298`) renames `scale`→`scales` and subsamples group scales. Target is **on-device ExecuTorch (mobile CPU/NPU) kernels, not CUDA** (README.md:62-70: "utilize the quantization kernels and achieve real-time speedup" via ExecuTorch). Therefore any end-to-end timing of the PyTorch/CUDA path in this repo measures FP16 compute plus fake-quant overhead (it is typically *slower* than the FP baseline), never real INT4 speedup.

Necessary because `rotate_embeddings` right-multiplies by R1 while `rotate_head` also right-multiplies by R1 — with shared storage the weight would be rotated twice (and the fusions differ: embeddings additionally get mean-subtracted).

## 6. Hidden-state basis after fusion (critical for integration)

**Yes — at runtime the entire residual stream is in the R1-rotated basis.** Evidence chain:
- `embed_tokens.weight = W_E @ R1` (`eval_utils/rotation_utils.py:55-60`) → layer-0 input is `h @ R1`.
- Every block reads the residual through input-side-rotated weights (`W @ R1` for q/k/v/up/gate, `:63-68, 83-89`) which cancels R1 internally, and writes back through output-side-rotated weights (`R1.T @ W` for o_proj/down_proj, `:71-80, 92-103`) so the residual additions stay in the R1 basis. Hence `model.layers[i]` outputs `h_i @ R1` activations, including the input to `model.model.norm`.
- `lm_head.weight = W_lm @ R1` (`:106-111`) consumes the R1-basis hidden state directly; logits are unchanged. (In the training model this is explicit at runtime: `hidden_states @ R1.T` before the un-fused lm_head, `train_utils/modeling_llama_quant.py:1381-1385`.)
- **RMSNorm is made scale-free first** by `utils/fuse_norm_utils.py`: `fuse_ln_linear` folds the norm's diagonal scale into the following linears — quote (`:26`): `linear.weight.data = (W_ * layernorm.weight.double()).to(linear_dtype)` (and folds any norm bias into linear bias, `:28-36`). `fuse_layer_norms` (`:39-75`) applies this to input_layernorm→{q,k,v}, post_attention_layernorm→{up,gate}, final norm→lm_head, then sets every norm weight to ones (`:64-67, 73-74`), and zero-centers the embedding rows (`:43-45`: `W_ - W_.mean(dim=-1)`). A weight-1 RMSNorm computes `x/rms(x)`, which commutes with any orthogonal R1 (rms is invariant), making the rotation exact. Order in `ptq_model`: `fuse_layer_norms` then `rotate_model` (`eval_utils/main.py:28-29`). So what is fused into `embed_tokens` = mean-centering + `@R1`; into `lm_head` = final-norm scale + `@R1`.
